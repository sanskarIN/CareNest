# Architectural Decisions

## ADR summary

1. **Local-first only for v1.** No account, network dependency, automatic cloud upload, or remote caregiver sharing.
2. **Layered solution.** Domain is framework-independent; Application defines use cases/contracts; Infrastructure owns SQLite, encryption and exports; App owns MAUI/platform UI.
3. **SQLite with schema migrations.** Versioned migrations and integrity checks keep restore and upgrades deterministic.
4. **Sensitive documents encrypted individually.** Imported health documents are AES-256-GCM encrypted with a per-installation random key stored through the platform secure secret store.
5. **Database-at-rest limits are explicit.** The SQLite database remains protected primarily by each platform application sandbox; full database encryption is not claimed.
6. **No dosage model.** Medicine strength and instruction are opaque user-entered text. Scheduling never computes a dose.
7. **Occurrences are materialized.** Future reminder occurrences are generated idempotently from user schedules so state changes and recovery are auditable.
8. **Notification payloads are privacy-minimized.** Default notification labels are generic; document contents and sensitive notes are never logged.
9. **Manual encrypted backups.** Backup archives use PBKDF2-HMAC-SHA256 + AES-256-GCM and require a user password; there is no background cloud upload.
10. **PDF reports are informational.** Exported reports carry a privacy and non-clinical disclaimer and avoid scoring or treatment conclusions.
11. **MVVM without a mandatory UI toolkit dependency.** Small internal observable/command primitives keep the app testable and reduce dependency surface.
12. **Platform notification limitations are surfaced.** The app reports permission, battery/exact-alarm limitations, and rebuilds schedules on startup and observed system changes where platform APIs permit.
13. **Runtime exception logging is metadata-only.** Global, UI, startup and reminder error paths do not pass full exception objects, messages, stack traces, health-record identifiers, document paths, or user-entered health text to the CareNest logger. Safe exception type/category metadata is evaluated only when the corresponding log level is enabled.
14. **Repository policy is executable.** Local-first, non-clinical, no-placeholder, no-common-secret-file, architecture, ViewModel, data-model, branding, async-safety and logging-privacy boundaries are protected by automated contract/policy tests in addition to documentation and review.
15. **Formatting is a platform-neutral CI gate.** Shared, Domain, Application, Infrastructure and all test projects must pass `dotnet format --verify-no-changes`; MAUI target compilation remains isolated to platform jobs with the appropriate workloads.
16. **Exact-head verification uses marker-only branches.** When a fresh PR-triggered matrix is required, a temporary branch is created from the exact intended `main` source SHA and adds only a marker under `build/verification/`. Any verification-relevant source change makes that PR stale; stale marker PRs are closed without merge and recreated from the corrected head.
17. **The SQLite advisory exception was temporary and has been removed after compatible remediation.** CareNest keeps `sqlite-net-pcl` `1.9.172` and `SQLitePCLRaw.bundle_green` `2.1.11` while central transitive pinning selects maintained native/provider leaves: `SQLitePCLRaw.lib.e_sqlite3` `3.53.3`, Android native `2.1.12`, and selected providers `2.1.12`. The exact `GHSA-2m69-gcr7-jv3q` `NuGetAuditSuppress` entry was removed and regression contracts prevent restoring the old package/suppression baseline. Packaged existing-database/encrypted-data compatibility remains a separate manual release gate rather than a reason to reintroduce the suppression.
18. **Release evidence is separate from release permission.** Automated CI, CodeQL, Dependency Audit and Release Evidence artifacts are necessary evidence but do not authorize production release by themselves. Manual device/accessibility testing, current store-policy review, signing/package validation and open-risk review remain independent release gates.
19. **Voluntary funding is outside the health-product entitlement model.** The fixed external Buy Me a Coffee destination opens only after explicit user action, receives no CareNest health payload, and never changes health behavior, reminder priority, emergency handling, support priority, or access to local data.
20. **Reminder planning windows are half-open and deterministic.** Planner windows include `fromUtc` and exclude `toUtc`, duplicate explicit clock times collapse to a stable occurrence key, and returned occurrences are chronologically ordered. These rules allow adjacent rebuild windows without boundary duplication.
21. **Invalid local reminder times are not medically interpreted.** If a user-entered local time does not exist during a daylight-saving spring-forward gap, the planner does not invent an alternative time. Ambiguous fall-back times use a deterministic offset choice so repeated rebuilds produce the same occurrence identity. Delivery limitations remain explicit and this behavior is organizational, not clinical.
22. **Medicine/schedule state gates automatic materialization.** Disabled schedules, as-needed schedules, and paused/completed/archived medicines produce no automatic reminder occurrences. Date boundaries and cycle/every-N-hours behavior come only from explicit user-entered schedule values.
23. **App-lock verifier buffers are treated as sensitive memory.** PINs are never persisted directly. CareNest stores a random salt and PBKDF2-HMAC-SHA256 verifier through the platform secret store, compares with a fixed-time primitive, and clears both derived and retrieved verifier buffers after verification paths where managed-memory control permits. App lock remains a local privacy barrier rather than whole-database/device encryption.
24. **WAL snapshot evidence must validate content, not only file existence.** Backup snapshot tests verify that committed records are present in the copied SQLite database, the copied database passes integrity checking, and pre-cancelled snapshot operations leave no output file.
25. **Reminder ownership is validated before materialization.** The planner rejects a schedule that does not belong to the supplied medicine, a medicine that does not belong to the supplied local profile, or a persisted schedule-time linked to another schedule. Archived profiles are also suppressed defensively. Ownership mismatches fail closed instead of silently creating reminders under another local entity.
26. **Reminder transport timestamps are explicit UTC contracts.** Planner windows and coordinator rebuild overrides require UTC `DateTime` values. Snooze actions require a future UTC timestamp. Local or unspecified values are rejected rather than silently reinterpreted, preventing clock-kind mistakes from becoming incorrect platform notification times.
27. **Randomized recurrence coverage must remain reproducible and non-clinical.** Property-style reminder tests use a fixed seed and explicit synthetic schedule values. They validate boundaries, uniqueness, ordering, selected-day masks, cycle arithmetic and elapsed-hour spacing without deriving any medical schedule from medicine text or health information.
28. **Documentation is implementation evidence, not permission to overclaim.** `docs/README.md` is the canonical documentation hub and subsystem documents must stay aligned with implemented behavior. Documentation-only commits after an exact verified runtime/test SHA do not establish a newer runtime verification baseline. Manual device/accessibility/store/signing work remains incomplete until actually performed, dependency suppression is never described as remediation, and time-sensitive store policy is reviewed at submission rather than frozen as permanent documentation truth.
29. **Appointment notification timestamps are explicit UTC contracts and denied permission fails safe.** `Appointment.StartsUtc` must be `DateTimeKind.Utc`; local/unspecified ticks are rejected rather than relabeled with `DateTime.SpecifyKind`. A save-time notification permission request that remains denied produces no platform schedule, and rebuild paths do not repeatedly request permission or schedule while permission remains denied. This is organizational scheduling integrity, not clinical timing validation.
30. **Document import uses compensating rollback across filesystem and SQLite.** Encrypted payload creation, metadata save, and audit save cross persistence boundaries that cannot be one SQLite transaction. Database-save failure removes the encrypted payload; audit failure after metadata save attempts to remove both the new metadata record and encrypted payload with non-cancelled cleanup. Incomplete rollback is surfaced explicitly rather than hidden. Abrupt process/OS termination remains a residual risk.
31. **Caller-owned cryptographic byte buffers are cleared after use where practical.** CareNest clears mutable app-lock verifier, document-master-key, backup-derived-key/salt, restore-key, and chunked-AEAD work buffers with `CryptographicOperations.ZeroMemory` when application code owns those arrays. This reduces known buffer lifetime but does not claim erasure of runtime/OS/secure-store/crash-dump copies.
32. **Decrypted backup package topology is allowlisted before extraction.** A valid backup contains only the expected manifest, SQLite database, optional/required 32-byte document key, and top-level `.cndoc` document entries. Duplicate, nested, unexpected, manifest-count-mismatched, or invalid-key layouts are rejected before extraction; path containment remains a second defense. This keeps restore behavior aligned with exactly the files CareNest consumes.
33. **New chunked encrypted streams use authenticated terminal framing v2 while legacy v1 remains readable.** Framing v2 authenticates each chunk's counter/length and adds an authenticated zero-length terminal bound to the next chunk counter, preventing chunk-boundary prefix truncation from being accepted as a complete new stream and rejecting trailing bytes. Existing framing-v1 CareNest documents/backups remain readable for compatibility and are not falsely represented as retroactively upgraded; removing v1 support requires an explicit migration/deprecation review.
34. **Platform reminder state is reconciled explicitly with persisted reminder state.** SQLite reminder rows and operating-system scheduled requests are separate state surfaces. CareNest cancels old platform requests before replacement, suppression, invalidation, or handled-state transitions; schedule edits retain enough occurrence identity for stale-request cleanup; medicine/profile/appointment persistence uses compensation where one surface can fail after the other.
35. **Handled reminder actions are cancellation-first and recoverable.** Taken, skipped, delayed, missed, snoozed, and cancelled actions cancel the existing OS request before committing the handled state. If later state persistence or snooze replacement scheduling fails, CareNest attempts non-cancelled restoration/rebuild and surfaces aggregate recovery failure instead of claiming contradictory state is consistent.
36. **Exact production tags run the full release automation set.** Tags matching `v*` trigger CareNest CI, CodeQL, Dependency Audit, Release Gate, and Release Evidence against the exact tagged commit. Release Evidence records tracked-source provenance/checksums, attempts all core evidence components, uploads evidence even after a component failure, and only then applies an aggregate pass/fail gate. A tag is not approved for publication until every required tag workflow plus manual/signing/store/data-compatibility evidence is complete.
